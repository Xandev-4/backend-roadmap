🌱 roadmap

Backend Engineering Plan 12 Weeks

Goal

Two deployable, resume-ready backend projects:

  1. A tested, containerized, CI/CD-deployed REST API
  2. An AI document Q&A service (RAG) with background jobs
Stack

Node.js 24 (LTS) + TypeScript, Fastify 5, Zod 4, PostgreSQL, Drizzle (stable 0.45.x) or Prisma, Redis, Docker, GitHub Actions, pgvector, BullMQ.

Pace

~5 focused sprints (25 min each) Mon to Fri, a longer flow session on Saturday, Sunday off.

How to read this file

  • Each day is a short list of tasks.
  • Search: lines are things to type into Google or YouTube (or the official docs).
  • Prefer official docs and short articles. Use YouTube for one concept at a time, not whole courses.

Reference videos

All three use Express + MongoDB + plain JavaScript. Your stack is Fastify + Postgres + TypeScript, so watch for the concepts, then rebuild in your stack. Don't switch to Mongo.

How to use them:

  • Watch only the section named in the Reference: line. Use the video's chapter list in the YouTube description to jump to it.
  • Watch 5-10 minutes, pause, then build that part yourself. Don't type along line by line.
  • Change something (rename entities, add a field) so you're not just copying.
  • Skip frontend parts, Gmail/Google OAuth setup, and paid third-party services.

Rules for every week

  • Start rule: first sprint of the day is "open the editor and write one line."
  • Stop mid-task: end each day on something unfinished so tomorrow's first step is obvious.
  • AI rule: you write the code. AI reviews it, explains errors, or gives a hint after 15 min stuck.
  • Explain-it-back: after each concept, write 3 lines in your own words in notes.md.
  • Docs-first: if a tutorial and the official docs disagree, trust the docs. Check the library version in the tutorial matches yours (Zod, Fastify, Drizzle change fast).
  • Saturday: ship the deliverable, update the README, push to GitHub.
  • Falling behind: extend the plan. Never skip Weeks 3, 4, 5.

Bonus project (optional, after Week 7): Postgres ledger

A small money-transfer API that teaches correctness under concurrency. It's a strong interview talking point, but don't start it until Projects 1 and 2 are on track.

Reference: Bank ledger video, the double-entry ledger, balance derivation, transfer flow, and idempotency sections. Skip Mongo specifics, NodeMailer, and the Render deploy.

  • Model it in Postgres: accounts, transactions, and an append-only ledger_entries table (debit/credit rows)
    • searchdouble entry bookkeeping database design
  • Compute balances from ledger entries with SQL (SUM with CASE), never store a mutable balance field
  • Make ledger rows immutable
    • searchpostgres prevent update delete trigger
  • Write the transfer as one transaction, locking rows
    • searchpostgres select for update
  • Add idempotency: a unique constraint on the idempotency key so a retried request can't double-charge
    • searchidempotency key api design
  • Write concurrency tests: two simultaneous transfers from the same account must never overdraw it
  • Reuse your auth, Docker, and CI from Project 1
